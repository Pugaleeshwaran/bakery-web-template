Rosewood — Bakery Website Template

A four-page bakery website in plain HTML, CSS and JavaScript. No build step, no npm, no database, no framework. Open a file, edit it, save, refresh.

If you read one thing, read this. Almost everything you want to change — your name, phone, address, hours, the entire menu, every price, the reviews, the FAQ — lives in a single file: assets/js/data.js. Open it in any text editor. It is heavily commented and organised into eight numbered sections.

Quick start top ↑

  1. Unzip the folder anywhere on your computer.
  2. Double-click index.html. The site opens in your browser and works immediately — you do not need a server, an internet connection (beyond fonts) or any software to install.
  3. Open assets/js/data.js in a text editor. Notepad and TextEdit are fine; VS Code is free and nicer.
  4. Edit section 1 — name, phone, email, address.
  5. Save, then refresh the browser (Ctrl+R, or Cmd+R on a Mac). Every page has updated.

Changes not showing? Your browser is holding an old copy. Do a hard refresh: Ctrl+Shift+R (Cmd+Shift+R on a Mac). See Troubleshooting.

Business details top ↑

File: assets/js/data.js → section 1

window.BK_CONFIG = {
  name:    'Rosewood Bakery',
  tagline: 'Freshly Baked With Love',

  phoneDisplay: '+1 (503) 555-0142',   // shown on the page
  phoneRaw:     '15035550142',         // digits only, country code first
  email:        'hello@example.com',

  addressLine1: '1420 Maple Avenue, Suite 3',
  addressLine2: 'Portland, OR 97205',
  ...
};

phoneRaw must be digits only, starting with your country code, with no +, spaces, brackets or dashes. It builds the order links, and they silently fail if it is wrong. USA/Canada 1, UK 44, Australia 61, India 91. A UK number 07700 900123 becomes 447700900123 — the leading 0 is dropped.

phoneDisplay is only ever shown to people, so format it however looks right for your country.

Menu & prices top ↑

File: assets/js/data.js → section 4

Every item is one block. To add a cake, copy an existing block, paste it, and change the values. Nothing else needs updating — the home page, the products grid, the search, the filters and the contact form's dropdown all read from this one list.

{
  id: 'lemon-cake', name: 'Lemon Drizzle Cake', category: 'cakes',
  price: 44, unit: '8-inch',
  desc: 'Zesty lemon sponge under a crackly sugar glaze.',
  tone: ['#F5E08A', '#C9A227'], featured: true, badge: 'New'
},
FieldRequiredWhat it does
idyesUnique, lowercase, hyphens only. Also used to find the photo.
nameyesShown on the card.
categoryyesMust match an id from section 3.
priceyesA plain number. No currency symbol, no quotes. 4.5 renders as $4.50.
unityesFree text after the price: '8-inch', 'each', 'per loaf'.
descyesOne or two sentences.
toneyesTwo colours. Used to draw an illustration until a real photo exists.
badgenoSmall label on the card: 'Bestseller', 'New'.
featurednotrue puts it in "Signatures" on the home page.
seasonalnotrue marks it as seasonal.
customnotrue points the button at the custom-order form.

Two rules that break the page if you get them wrong. Every block must end with a comma, except you may leave it off the last one. And every apostrophe inside a quoted string must be escaped: write 'Baker’s pick' with a curly apostrophe, or "Baker's pick" with double quotes. A straight ' inside single quotes ends the string early and the page goes blank. See Troubleshooting.

Categories

Section 3 holds the five category cards and the filter tabs. from is the lowest price in that category, shown as "from $38". Keep it in step with your prices — nothing calculates it for you.

Photos top ↑

There are two ways, and the first needs no code at all.

The easy way — name the file after the item

Drop your photo into assets/images/ and name it after the item's id. That is the whole job.

assets/images/red-velvet-cake.webp   → becomes the Red Velvet Cake photo
assets/images/classic-brownie.jpg   → becomes the Classic Brownie photo

.webp, .png, .jpg and .jpeg are all tried automatically, in that order. The full list of names is in the reference table.

The other way — point at a file you already have

If your file is called something else, list it in section 2 of data.js:

window.BK_IMAGES = {
  'red-velvet-cake': 'my-red-velvet-photo.jpg',
  ...
};

A missing photo can never break the page. If an item has no photo, it falls back to its category photo. If that is missing too, it falls back to a hand-drawn illustration in the item's own colours. You will never see a broken-image icon. Open the browser console (F12) to see a list of anything that fell back.

The hero slideshow top ↑

The big round cake on the home page can be a single photo or a slideshow that cross-fades every five seconds. Section 2 of data.js:

// one photo — a still picture
'hero-cake': 'my-best-cake.webp',

// a list — fades from one to the next every 5 seconds
'hero-cake': [
  'head-coco.webp',
  'head-red.webp',
  'head-bendo.webp'
],

// empty — keeps the built-in hand-drawn cake illustration
'hero-cake': '',

Any number of photos works. Because the image is shown inside a circle, use square photos with the cake centred — anything at the corners gets cropped away.

To change the five seconds, open assets/js/app.js and edit HERO_INTERVAL near the top of the hero section. It is in milliseconds, so 8000 is eight seconds.

The slideshow pauses when the tab is in the background, and it does not run at all for visitors who have "reduce motion" switched on in their operating system. Both are deliberate.

Page background photos

Each page has its own background, set in assets/css/base.css:

body.page-home     { --banner-image: url('../hero-bg/hero-home.webp'); }
body.page-products { --banner-image: url('../hero-bg/hero-products.webp'); }
body.page-about    { --banner-image: url('../hero-bg/hero-about.webp'); }
body.page-contact  { --banner-image: url('../hero-bg/hero-contact.webp'); }

Replace those files, keeping the same names, and nothing else changes. Two variables just below control how much dark veil sits over them — --banner-veil and --hero-veil. Lower numbers show more photo; higher numbers keep the text more readable. Check both themes after changing them.

Colours top ↑

File: assets/css/base.css, the block right at the top.

Every colour in the design comes from that one block, so changing a variable there changes it everywhere at once.

:root {
  --gold:      #C9A227;   accent — buttons, prices, rules
  --gold-rgb:  201, 162, 39;
  --espresso:  #170D07;   darkest background
  --cream:     #FBF3E4;   light sections
  --wine:      #8E2436;   secondary accent
  ...
}

Change both lines for a colour that has an -rgb twin. --gold is used directly; --gold-rgb is used to build see-through versions like rgba(var(--gold-rgb), .4). If you change one and not the other, glows and borders keep the old colour. Convert your hex with any "hex to rgb" search — #C9A227 is 201, 162, 39.

Theme switcher top ↑

The template ships with two finished themes and a floating swatch in the corner to flip between them:

ThemeLook
DefaultDark espresso and gold. Rich, evening, premium.
BlushLight pink, cream and gold. Soft, romantic, daytime.

The switcher is a decision tool for you, not really a feature for your customers. Once you have chosen, remove it — a live business site showing visitors a theme picker looks unfinished.

  1. Open the site and click the swatch until you have the theme you want.
  2. Note which one it is. To make it the permanent default, open assets/css/base.css and move that theme's colour values into the main :root block.
  3. Delete this line from all five HTML files: <script src="assets/js/theme.js?v=1"></script>

Leaving theme.js in place is harmless if you want visitors to be able to switch. Their choice is remembered in their own browser.

They load from Google Fonts. To swap one, pick a font at fonts.google.com, copy its <link> tag into all five HTML files in place of the existing one, then update the font name in assets/css/base.css (search for --font-).

To make the site work fully offline, download the font files, put them in assets/fonts/, and replace the Google Fonts <link> with a local @font-face block. All three fonts are under the SIL Open Font Licence, which permits this.

To edit the wording, open the file and change the text inside the <text> tags. To use your own logo instead, save it as logo.svg (or logo.png) and update the <img src="..."> tags — there are three or four in each HTML file, so search for logo. in each.

SVG is XML. Never put two hyphens next to each other inside an SVG comment. It is legal in HTML and illegal in XML, and the whole file silently refuses to render.

Order buttons top ↑

Every "Order Now" button, the floating bubble and the contact form all use the same channel, set in section 1 of data.js:

orderChannel: 'whatsapp',   // 'whatsapp' | 'sms' | 'phone'
orderLabel:   'WhatsApp',   // the wording shown on the buttons
SettingWhat happens when someone tapsSuggested label
'whatsapp'WhatsApp opens with the message already typed'WhatsApp'
'sms'The phone's text app opens with the message already typed'text'
'phone'Dials your number straight away'phone'

The links, the visible wording and the icon all follow the setting. In the USA, 'sms' is usually the better choice; WhatsApp is the norm in most of the rest of the world.

The contact form does not need a backend. It gathers what the customer typed, builds a tidy order message and hands it to the chosen channel. Nothing is stored, nothing is emailed, and there is no server to pay for or maintain. If you would rather receive orders by email, replace the form's submit handler in assets/js/app.js with a service like Formspree or Netlify Forms.

SEO top ↑

Each page already carries a title, a description, a canonical URL, Open Graph and Twitter share cards, and Bakery structured data that tells Google your address, hours and prices. All of it is at the top of each HTML file, under a TEMPLATE TODO comment.

  1. In all five HTML files, replace every https://www.example.com with your real domain.
  2. Rewrite each <title> and <meta name="description"> to name your bakery and your town. Titles work best around 55–60 characters, descriptions around 150.
  3. In the application/ld+json block, fill in your real address, phone, hours and prices. Wrong details here are worse than none — Google shows them to people.
  4. Do the same in sitemap.xml and robots.txt.
  5. Replace assets/images/og-cover.jpg (1200 × 630) with your own. This is the picture people see when your link is shared.
  6. Once you are live, check the structured data at Google's Rich Results Test, then submit your sitemap in Search Console.

For a local bakery, a Google Business Profile matters more than anything on this list. It is free, it puts you on Maps, and it is what most "bakery near me" searches actually return. Set it up first, then use the same name, address and phone here — matching details across the two is exactly what Google is looking for.

Going live top ↑

Hosting

This is a static site, so hosting is free or nearly free. The easiest route: drag the whole folder onto Netlify Drop. It is online in about ten seconds, with HTTPS included. Vercel, Cloudflare Pages, GitHub Pages and ordinary cPanel hosting all work the same way — upload the folder, done. There is nothing to install and no database.

Troubleshooting top ↑

The page is blank, or nothing loads

Almost always a typo in data.js. Press F12, open the Console tab, and read the red message — it names the line number. The three usual culprits:

MistakeFix
Missing comma between two blocksEvery block ends with , except the last
A straight apostrophe inside single quotes, like 'Baker's pick'Use double quotes, "Baker's pick", or a curly ’
A missing { } [ or ]Undo your last edit and redo it more slowly

My changes are not showing

Hard refresh: Ctrl+Shift+R (Cmd+Shift+R on a Mac). If that fixes it but visitors still see the old version after you upload, bump the version number on the asset links in the HTML — change every ?v=1 to ?v=2. That is exactly what it is for.

A photo is not appearing

  • Check the filename matches the item's id exactly — lowercase, hyphens, no spaces.
  • Check the extension. .WEBP is not .webp on a real web server, even though it works on Windows.
  • Check it is in assets/images/, not a subfolder.
  • Open the console (F12) — the template logs what it tried and what it fell back to.

The order button does nothing

phoneRaw is wrong. It must be digits only, starting with the country code, with no +, spaces, brackets or dashes. Test on a real phone, not on a desktop — sms: and tel: links do nothing on most desktops.

Text is hard to read over my new background photo

In assets/css/base.css, raise --banner-veil and --hero-veil — they darken the photo behind the text. Check both themes; a photo that reads well on the dark theme can wash out on the blush one.

Animations feel like too much

Delete <script src="assets/js/scroll.js?v=1"></script> from the HTML files. Everything still renders and the layout is unaffected; only the reveal animations stop.
